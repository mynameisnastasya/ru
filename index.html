Архитектура

Два workflow. Один контент‑агент.

Первый отвечает за публикации. Второй — за новые ответы и решение, стоит ли на них реагировать автоматически.

API flow

Публикация в два запроса.

Сначала создаём контейнер с текстом, затем публикуем его. Токен держим в secret storage, а не в промптах или таблицах.

1. Create container
POST https://graph.threads.net/v1.0/me/threads

media_type=TEXT
text=ТЕКСТ_ПОСТА
access_token={{THREADS_TOKEN}}
2. Publish
POST https://graph.threads.net/v1.0/me/threads_publish

creation_id={{CONTAINER_ID}}
access_token={{THREADS_TOKEN}}
Replies

Бот отвечает только там, где это уместно.

Отвечать

✓На нормальные вопросы по теме.
✓На содержательную дискуссию и возражения.
✓На шутки, когда можно естественно поддержать тон.
✓На комментарии, где есть уверенный фактический ответ.

Не отвечать автоматически

×Спам, повторы и бессмысленные сообщения.
×Конфликты, способные навредить репутации.
×Юридические, медицинские и финансовые вопросы без ручной проверки.
×Ситуации, где модель не уверена в фактах.

Feedback loop

Пост опубликован ↓ через 24 / 48 часов получить метрики ↓ сохранить в базу ↓ LLM анализирует: — хуки — темы — длину — ответы ↓ использует выводы в следующих публикациях
Промпт

Стиль задаётся правилами, а не магией.

Ты автор моего Threads. Тематика: [описание] Целевая аудитория: [описание] Стиль: коротко, разговорно, конкретно. Не используй: — канцелярит — «в современном мире» — «давайте разберемся» — чрезмерные эмодзи — фальшивые истории — придуманные цифры Структура: 1. Сильная первая строка. 2. Одна мысль. 3. Конкретный пример или наблюдение. 4. Финал, который естественно вызывает обсуждение. Не повторяй идеи предыдущих постов. Верни только текст публикации.
