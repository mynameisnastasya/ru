# WINK Brand System

Статус: внутренний стандарт продукта, дизайна, контента и разработки.

## 1. Одна фраза

**WINK — когда надо красиво поздравить.**

WINK — современный бренд подарков и красивых поздравлений. Клиент выбирает повод и настроение, WINK берёт на себя вкус, сочетания, композицию, детали и результат.

## 2. Главный продуктовый принцип

**Меньше выбора. Больше вкуса. Меньше хлопот. Больше эмоции.**

Мы не увеличиваем количество опций ради ощущения ассортимента. Мы уменьшаем когнитивную нагрузку и оставляем только решения, которые выглядят хорошо и имеют операционный смысл.

Нельзя:
- 84 цвета в одном selector;
- бесконечные SKU с минимальными различиями;
- «напишите менеджеру для расчёта» для стандартного продукта;
- технические параметры латекса, грузиков и обработки как клиентский выбор;
- фальшивые скидки и искусственная срочность.

Нужно:
- 2–6 сильных готовых вариантов;
- понятная цена до контакта с менеджером;
- персонализация только там, где она реально нужна;
- server-side validation обязательных полей;
- готовое решение вместо перекладывания профессионального выбора на клиента.

## 3. Клиентская задача

Пользователь не приходит «купить латекс». Его задача звучит примерно так:

> Хочу красиво поздравить человека и не заказать какую-нибудь хуйню.

Поэтому интерфейс сначала должен отвечать на вопросы:
1. Кого поздравляем?
2. Какой повод?
3. Какое настроение?
4. Какой масштаб / бюджет?
5. Какая персонализация действительно нужна?

Только после этого показывается продукт.

## 4. Основные аудитории

### Женщины 20–35
Важны эстетика, эмоция, современность, фото, простота покупки и ощущение «это в моём стиле».

### Мужчины, покупающие подарок девушке
Нужен самый короткий сценарий выбора. Не спрашивать «сатин или металлик». Предлагать законченные решения под повод и бюджет.

### Родители
Ключевые сигналы: надёжность, безопасность, своевременность, понятная цена.

### Компании
Отдельное B2B-направление после стабилизации B2C.

## 5. Позиционирование

Категория: современный бренд подарков и красивых поздравлений.

Обещание: красивый результат без сложного выбора.

Точка зрения: клиент не обязан разбираться в шарах, чтобы красиво поздравить близкого. Хороший сервис должен сделать профессиональный выбор за него.

## 6. Tone of Voice

Основной язык — русский.

Английский допустим точечно: WINK, название коллекции или короткий декоративный маркер. Английский не используется только ради «премиальности».

Голос WINK:
- короткий;
- понятный;
- тёплый;
- уверенный;
- современный;
- иногда ироничный;
- без давления.

Не используем:
- «Уважаемые клиенты»;
- «Предлагаем вашему вниманию»;
- «Создадим незабываемую атмосферу вашего торжества»;
- «Огромный выбор шаров на любой вкус»;
- канцелярит и искусственный luxury-язык.

Принцип текста: говорить про момент и результат, а не про складскую единицу.

Плохо: «Композиция из 15 латексных воздушных шаров».

Хорошо: «15 шаров, которые моментально меняют комнату».

## 7. Визуальный код

Ощущение: **чисто + женственно + современно + эмоционально + дорого без показухи**.

База:
- молочный;
- тёплый белый;
- blush / приглушённый розовый;
- chrome / холодное серебро;
- графитовый / почти чёрный.

Дополнительные палитры допускаются для детей, мужских и сезонных сценариев, но не должны разрушать общую ДНК.

Не используем:
- радугу в UI;
- кислотные CTA;
- визуальный шум;
- баннерную механику «АКЦИЯ!!!»;
- дешёвые party-shop паттерны.

## 8. Фотография

Формула: **идеальный продукт + живая фотография**.

Фото должно ощущаться как реальный момент через несколько минут после доставки, а не как стерильный каталог или AI-реклама.

Для каждого ключевого SKU нужны минимум 5 типов кадров:
1. главный продающий кадр;
2. кадр с человеком для масштаба и эмоции;
3. деталь / фактура / chrome / лента / надпись;
4. интерьерный кадр;
5. живой вертикальный кадр для Stories/Reels.

Допустимая среда: реальные квартиры, спальни, отели, прихожие, окна, кровати, руки, платья, халаты, телефоны, бытовая жизнь.

## 9. Ассортимент

Каталог работает как конструктор, а не как склад.

Клиент выбирает:
1. повод;
2. формат;
3. размер;
4. палитру;
5. персонализацию.

Каждая позиция должна выполнять хотя бы одну функцию:
- регулярно ищется;
- хорошо продаётся;
- повышает средний чек;
- усиливает бренд;
- создаёт сильный контент;
- ведёт к повторной покупке.

Если позиция не выполняет ничего — убрать.

## 10. Сервис

Сервис является частью продукта.

Правила:
- не задавать 20 вопросов;
- если данных достаточно — принимать профессиональное решение самим;
- предлагать максимум 2–3 варианта;
- не перекладывать подбор на клиента;
- обещанный срок, внешний вид и качество считаются частью заказа, а не «деталями».

Плохо: «Какие хотите оттенки?»

Хорошо: «Вам ближе нежный розовый с серебром или спокойный молочный с chrome?»

## 11. Целевой клиентский путь

1. Увидел — Reels / Instagram / Flowwow / рекомендация / поиск.
2. Понял — за первые секунды понимает что продаём, стиль, примерный чек и как заказать.
3. Выбрал — несколько понятных решений, не сотня товаров.
4. Персонализировал — цвет, цифра, надпись, открытка, время.
5. Оплатил — минимум коммуникации.
6. Получил — вовремя, красиво, предсказуемо.
7. Поделился — естественный запрос UGC.
8. Вернулся — следующая важная дата.

## 12. Website rules

Главная страница обязана за 5 секунд сообщить:
- WINK помогает красиво поздравить;
- выбор уже отфильтрован;
- можно выбрать готовое решение или собрать допустимую конфигурацию;
- цена прозрачна;
- оформление не требует обязательной переписки.

Приоритетная архитектура:
- Главная;
- Каталог;
- День рождения;
- Любовь;
- Дети;
- WOW;
- Собрать свой;
- PDP;
- Корзина / checkout;
- статус заказа;
- staff backoffice.

Новые страницы добавляются только если упрощают выбор или обслуживание. Не плодить категории ради SEO без продуктового смысла.

## 13. Checkout rules

Checkout строится вокруг подарка, а не вокруг аккаунта.

Нужно поддерживать:
- подарок себе / другому человеку;
- данные получателя отдельно от покупателя;
- анонимного отправителя;
- «не звонить получателю»;
- текст открытки / сообщения;
- адрес и время;
- guest checkout;
- серверную проверку цены и конфигурации;
- идемпотентное создание заказа.

## 14. Операционная система

WINK не должен зависеть от памяти одного человека.

Обязательные стандарты:
- принятие заказа;
- закупка;
- сборка;
- QC;
- упаковка;
- доставка;
- задержка / проблема;
- возврат;
- фотографирование;
- публикация контента;
- учёт клиента.

Каждая ошибка должна превращаться в изменение процесса, а не в одноразовый ручной фикс.

## 15. Клиентский капитал

Каждый покупатель должен попадать в систему вместе с:
- именем;
- получателями;
- важными датами;
- предыдущими заказами;
- любимыми палитрами;
- средним чеком;
- источником заказа.

Цель — не покупать одного и того же клиента заново рекламой перед каждой датой.

## 16. Денежная логика

Растим не только количество шаров и заказов.

Основные рычаги:
- количество заказов;
- средний чек;
- маржинальность;
- дополнительные продажи;
- повторные покупки;
- корпоративные заказы.

Средний чек растёт через ценность: композиция → цифра → открытка → фото → подарок → оформление пространства → точное время доставки.

## 17. Контент

Контент всегда выполняет одну из четырёх задач:
1. взгляд — показываем вкус WINK;
2. метод — показываем профессионализм;
3. доказательства — заказы, отзывы, UGC, реакции;
4. жизнь бренда — команда, сборка, доставка, ошибки, рабочие моменты.

Контент должен провести человека через три состояния:
- «это про меня»;
- «они понимают, что делают»;
- «я хочу это».

## 18. Метрики

Еженедельно:
- заказы;
- выручка;
- средний чек;
- себестоимость;
- валовая маржа;
- прибыль;
- новые / повторные клиенты;
- доля повторных;
- продаваемость SKU;
- маржинальность SKU;
- просмотры без покупки;
- источник заказа;
- стоимость привлечения;
- переходы;
- заявки;
- конверсия в оплату.

## 19. Фильтр любого нового решения

Перед продуктом, функцией, постом, партнёрством, упаковкой или UI-паттерном задаём пять вопросов:

1. Это красиво?
2. Это упрощает жизнь клиента?
3. Это соответствует WINK?
4. Это имеет экономический смысл?
5. Это можно повторить и масштабировать?

Если три ответа «нет» — не делаем.

## 20. Definition of done для клиентской функции

Функция считается готовой только если:
- она упрощает путь клиента или работу команды;
- не увеличивает выбор без причины;
- использует русский как основной язык;
- не нарушает визуальный код;
- цена и бизнес-правила проверяются сервером;
- мобильный сценарий полноценный;
- есть понятное состояние ошибки;
- есть событие/данные для последующего анализа;
- функцию можно обслуживать без знания «секретной логики основателя».
